## 5. 修复与验证链路

首轮规则基线仅 4/12（33.3%）。失败轨迹驱动了以下收敛修复：

1. 用 `GetReachablePositions` 和确定性最远点采样替代消耗大量原地转向的螺旋搜索。
2. 搜索抓取目标时逐个打开关闭容器，并在水平、向下 30°、向上 30°视角探测；无目标则关闭容器，避免门板遮挡。
3. 记录“容器类型 → 已知可达视点”，抓取后优先回访目标容器视点。
4. 放置失败强制换位；普通 `PutObject` 仅在“无有效落点”时使用一次 `forceAction=True` 兜底，并继续要求完整父子容器状态验证。
5. OpenAI 兼容客户端增加 60 秒超时和有限重试，防止单次 API 请求阻塞整批。
6. 首轮完整 LLM 对照为 7/12（58.3%）；轨迹显示模型重复 `scan/move_to`、绕开 `pick/place` 恢复入口。System Prompt 明确内置搜索契约后，最终提升为 10/12。

## 6. 剩余失败与边界

### a08：任务集兼容性缺陷

AI2-THOR 对所有可见 Drawer 均返回 `Cup ... cannot be placed in Drawer`；受控 `forceAction` 仍返回 `No valid positions to place object found`。该关系在当前模拟器版本中不可满足，因此保持失败，没有绕过语义验证。

### a12：持有物体后的放置搜索仍有缺口

CreditCard 能被找到并抓取，但持有物体时部分可达点传送发生 hand-object collision，Drawer 搜索在 20 步内未收敛。这是非阻断的后续优化项，不影响 10/12 门禁结论。
